# Architecture｜TasteMap Date

## Product Goal

TasteMap Date 是一個「食物優先」的約會 MVP。核心理念是透過共同的飲食喜好、大略約會地區、星座元素親和力，以及 AI 生成的低壓力邀約建議，幫助用戶發現彼此，降低第一次對話的壓力。

## High-Level Architecture

```
Browser (Next.js SSR/CSR)
  │
  ├── /            → Landing Page
  ├── /onboarding  → Profile creation (stored in localStorage)
  ├── /map         → TasteMap with Leaflet (SSR disabled)
  └── /inbox       → Date request inbox (accept/reject)
  │
  └── Next.js Route Handlers (API)
        ├── GET  /api/profiles
        ├── POST /api/match-advice   → Anthropic Claude API
        ├── POST /api/date-requests  → Firestore mode only
        ├── GET  /api/date-requests  → Firestore mode only
        └── PATCH /api/date-requests/:id
```

## Frontend

- **Next.js App Router** with TypeScript
- **Tailwind CSS** + **shadcn/ui** for UI components
- **Leaflet / React Leaflet** for the taste map (dynamic import, SSR disabled)
- **React Hook Form** + **Zod** for onboarding form validation
- **Zustand** for client-side state (selected candidate, filters)
- **lucide-react** for icons

## Backend

- **Next.js Route Handlers** running on Node.js
- **Anthropic Claude API** for AI invite suggestion generation
- Deterministic fallback when `ANTHROPIC_API_KEY` is missing
- Match scoring is pure rule-based functions — AI is not in the decision path

## Data Strategy

- 240 deterministic mock users generated by `scripts/generate-mock-users.ts`
- Seeded with a fixed seed for reproducibility
- Mock users committed to `src/data/mock-users.generated.json`
- No real addresses — approximate Taipei/New Taipei area coordinates with jitter
- Mutable state (date requests) stored via `DateRequestStore` adapter:
  - **local mode**: browser `localStorage`
  - **firestore mode**: GCP Firestore via `firebase-admin`

## Why Mock Profiles Are Acceptable

This is an interview MVP with a 3-day timebox. The goal is to demonstrate product thinking and full-stack ability, not database design. Deterministic mock data is reproducible, fast to demo, and avoids privacy concerns entirely.

## Why DateRequestStore Is Behind an Adapter

The adapter pattern allows switching from `localStorage` to Firestore without changing any UI code. This demonstrates architectural thinking and makes the demo robust even without GCP credentials.

## GCP Deploy Strategy

```
GitHub Actions (push to main)
  → typecheck + test + build
  → Docker build
  → Artifact Registry push
  → Cloud Run deploy
```

- **Cloud Run** for zero-cold-start-management, pay-per-use, HTTPS out of the box
- **Artifact Registry** for Docker image storage
- **Secret Manager** for `ANTHROPIC_API_KEY`
- **Workload Identity Federation** — no long-lived service account keys in GitHub

## Safety Constraints

- No exact home addresses — all coordinates are approximate area centers + jitter
- Location labels say "推薦約會區域" not "住家位置"
- No real user PII in mock data
- AI invite suggestions are low-pressure copy, not compatibility claims
